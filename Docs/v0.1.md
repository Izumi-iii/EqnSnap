# EqnSnap v0.1 实施计划

> 更新日期：2026-07-16  
> 文档状态：规划稿  
> 目标平台：macOS 13.0+  
> 相关文档：[Swift 架构](v0.1-swift-architecture.md) · [模型方案](v0.1-model.md) · [集成契约](v0.1-integration.md)

## 1. v0.1 的目标

EqnSnap v0.1 要验证一个最小但完整的产品闭环：

```text
全局快捷键或菜单栏入口
    → 框选屏幕中的单行印刷公式
    → 本地 pix2tex Core ML 识别
    → 显示可编辑 LaTeX 和渲染预览
    → 复制纯 LaTeX
```

v0.1 的判断标准不是功能数量，而是这条链路能否在真实使用中稳定、快速、可纠错地完成。

## 2. 当前假设

以下内容是本阶段的工作假设，需要通过模型转换和用户测试验证：

- pix2tex 官方预训练权重足以覆盖清晰、常规、单行印刷公式，不从头训练模型。
- FP16 Core ML 模型包体目标约 60 MB，但最终大小以实际转换产物为准。
- 普通单行公式端到端识别 P50 目标不超过 1 秒、P95 目标不超过 2 秒。
- 固定高度、受限宽度的输入策略能够满足首版精度和 Core ML 性能要求。
- 确定性 Argmax 解码可能比官方随机采样更适合桌面工具，但只有在测试集上无明显精度下降时才采用。
- 首版仅依赖屏幕录制权限；不使用窗口吸附时不应要求辅助功能权限。

若任一假设不成立，应先调整实现方案或产品边界，不应直接扩大为云端识别或重新训练模型。

## 3. 功能范围

### 3.1 P0：必须完成

| ID | 功能 | 完成条件 |
|---|---|---|
| BAS-001 | 菜单栏应用 | 启动后常驻菜单栏，不自动打开普通主窗口 |
| BAS-002 | 全局快捷键 | 可注册默认快捷键，可从菜单栏触发同一流程 |
| BAS-003 | 权限引导 | 缺少屏幕录制权限时说明原因并可跳转系统设置 |
| CAP-001 | 区域框选 | 在鼠标所在显示器显示遮罩，可任意方向拖出矩形 |
| CAP-002 | 取消 | `Esc` 或无效选区立即结束，不进入识别 |
| CAP-003 | Retina 坐标 | 截图像素与屏幕点坐标正确映射，不偏移、不越界 |
| CAP-004 | 单显示器策略 | 支持多显示器，但一次只在鼠标所在显示器内选择 |
| REC-001 | 本地模型 | 应用离线加载 pix2tex Core ML 产物，无 Python 运行时 |
| REC-002 | 识别流程 | 完成预处理、Encoder、Decoder 和 Tokenizer 解码 |
| REC-003 | 取消与过期结果 | 新旧请求不会互相覆盖，关闭结果后旧异步回调被丢弃 |
| REC-004 | 失败恢复 | 识别失败时保留截图，允许重试或关闭 |
| RES-001 | 结果浮层 | 显示原截图、识别状态、LaTeX 源码和预览 |
| RES-002 | 编辑 | LaTeX 可修改，预览随修改更新并处理渲染失败 |
| RES-003 | 重试 | 使用同一张截图重新识别，不要求再次截图 |
| OUT-001 | 复制 | 将纯 LaTeX 写入剪贴板，不自动添加 `$` 或 `$$` |
| ERR-001 | 用户可理解的错误 | 权限、无效选区、模型加载、识别超时和剪贴板错误有明确提示 |

### 3.2 P1：v0.1 可选增强

只有 P0 主链路稳定后才处理：

- 设置默认快捷键。
- 启动时模型预热开关。
- 复制成功后自动关闭结果浮层。
- 记住结果浮层位置。
- 行内 `$...$` 和块级 `$$...$$` 的复制选项。
- 本地匿名性能日志开关；只记录耗时和错误类型，不记录截图或 LaTeX。

### 3.3 不进入 v0.1

- 手写公式、矩阵和复杂多行公式的质量承诺。
- 历史记录、搜索、收藏和数据库。
- 云端 OCR、账号、同步和订阅系统。
- 整篇 PDF、通用文字、表格和化学式识别。
- 标注、保存截图、贴图和窗口自动吸附。
- 模型插件市场、通用依赖注入框架或远程模型下载器。

历史记录可以在 v0.2 评估。v0.1 不提前建立空的 Repository 或持久化层；截图只在当前会话的内存中保留。

## 4. 用户流程

### 4.1 正常流程

1. 用户按全局快捷键。
2. 应用检查屏幕录制权限和当前工作流状态。
3. 应用获取鼠标所在显示器的冻结画面并显示选区遮罩。
4. 用户拖动选区，松开鼠标后立即提交。
5. 应用裁切像素图，关闭遮罩，显示“识别中”结果浮层。
6. 模型完成识别，LaTeX 源码和预览同时出现。
7. 用户检查或修改源码。
8. 用户复制纯 LaTeX；按设置决定是否关闭浮层。

### 4.2 会话规则

- 任意时刻只有一个活动的截图、识别或结果会话。
- 结果浮层存在时再次触发快捷键，v0.1 先聚焦现有结果，不覆盖当前内容。
- 识别过程中关闭浮层会取消任务；无法真正中止的 Core ML 调用，其结果也必须因 session ID 不匹配而被丢弃。
- 识别失败时保留当前截图，用户可重试。
- 应用退出或会话结束后释放截图及中间张量。

### 4.3 键盘规则

| 场景 | 按键 | 行为 |
|---|---|---|
| 框选中 | `Esc` | 取消截图 |
| 结果浮层 | `Cmd-C` | 焦点不在编辑器选区时复制完整 LaTeX |
| 结果浮层 | `Cmd-Return` | 复制完整 LaTeX |
| 结果浮层 | `Esc` | 关闭浮层 |
| LaTeX 编辑器 | 常规编辑快捷键 | 保持系统文本编辑行为 |

`Cmd-C` 的焦点冲突需要在实现时验证。若无法无歧义地区分文本选区和整段复制，v0.1 只保留复制按钮与 `Cmd-Return`。

## 5. 软件分层

```text
EqnSnap App Target
    │
    └── EqnSnapApplication     组合根、应用生命周期、场景路由
            ├── EqnSnapUI              SwiftUI 页面与 AppKit 窗口
            ├── EqnSnapPresentation    工作流和 ViewModel
            ├── EqnSnapPlatform        截图、权限、快捷键、剪贴板
            ├── EqnSnapRecognition     Core ML、预处理、解码、Tokenizer
            └── EqnSnapCore            值类型、协议、状态、错误
```

原则：

- Core 不依赖 SwiftUI、AppKit、Core ML 或具体模型。
- 系统 API 和模型实现通过协议注入，不在 View 中直接调用。
- App Target 只负责创建依赖和启动，不承载业务逻辑。
- v0.1 使用显式初始化器组装依赖，不引入第三方 DI 容器。
- 对未来的扩展点使用窄协议；没有第二个实现需求的内部细节不抽象。

详细设计见 [v0.1-swift-architecture.md](v0.1-swift-architecture.md)。

## 6. 实现里程碑

### M0：固定基线与验收样本

- 固定 Python、pix2tex、PyTorch 和 coremltools 版本。
- 收集 100–300 张目标场景公式，记录期望 LaTeX。
- 区分简单、一般、困难和明确超出范围的样本。
- 保存 Python 基线输出、耗时和模型版本。

退出条件：测试集可重复运行，产品支持范围有可量化样本。

### M1：Core ML 可行性原型

- 转换 Encoder 和单步 Decoder。
- 对比 PyTorch 与 Core ML 的中间特征、logits 和 Token 序列。
- 实现最小 Swift 命令行或单元测试推理链路。
- 测量 FP16 包体、首次加载、热启动、P50/P95 和峰值内存。

退出条件：至少一组固定图片在 Swift/Core ML 中得到与 Python 可接受一致的结果。

### M2：工程骨架与 Core 状态机

- 新建 `Packages/EqnSnapKit` 和分层 Targets。
- 定义截图、识别、剪贴板等 ports。
- 实现单会话工作流和 session ID 过期保护。
- 为 reducer/state machine 编写单元测试。

退出条件：使用 fake ports 可完整模拟成功、取消、失败、重试和关闭。

### M3：截图闭环

- 从 Snapio 迁移最小坐标、显示器、截图后端和快捷键代码。
- 简化选区状态机：拖选、边界裁切、`Esc`、mouse-up 提交。
- 验证 macOS 13、Retina、非整数缩放和双显示器。
- 只要求屏幕录制权限。

退出条件：截图测试工具能稳定返回正确像素区域，不调用模型。

### M4：识别服务接入

- 将 `.mlpackage` 编译产物、Tokenizer 和 manifest 加入应用资源。
- 实现 Swift 预处理、Encoder、Decoder 循环和结果规范化。
- 增加取消、超长序列、资源缺失和内存错误处理。
- 用 golden fixtures 验证 Python 与 Swift 一致性。

退出条件：截图结果可进入本地模型，并稳定返回 LaTeX。

### M5：结果浮层与编辑

- 使用 `NSPanel + NSHostingController` 承载 SwiftUI 结果视图。
- 显示原图、状态、源码、预览、复制、重试和关闭。
- 接入离线 LaTeX 渲染器，并为不支持的宏提供源码回退。
- 完成键盘和 VoiceOver 基础支持。

退出条件：无需完整主窗口即可完成识别、修正和复制。

### M6：集成、性能和发行前检查

- 跑完整内部测试集和关键 UI 流程。
- 检查应用冷启动、模型常驻内存、连续识别和任务取消。
- 检查模型、Tokenizer、渲染库及迁移代码的许可证声明。
- 验证无网络环境、干净用户目录和权限被拒绝的情况。

退出条件：满足第 7 节验收标准，或明确记录未满足项和下一步决策。

## 7. v0.1 验收标准

### 7.1 功能验收

- P0 功能均有手工或自动化验收记录。
- 连续完成 20 次截图识别，不出现窗口残留、会话串线或崩溃。
- 取消、失败、重试和关闭不会留下不可恢复状态。
- 双显示器及 Retina 场景的截图区域与用户选择一致。
- 断网后所有核心功能仍可使用。

### 7.2 模型验收

- 在冻结的内部测试集上记录 exact match、规范化 match 和人工可接受率。
- Core ML 相对 Python 基线的质量下降必须可解释并处于接受范围。
- FP16 为首个发布候选；8-bit 只有在质量无明显下降后才考虑。
- 不用单张示例或主观印象替代完整测试集。

### 7.3 性能验收

| 指标 | 目标 | 备注 |
|---|---:|---|
| 截图遮罩出现 | 用户感知即时 | 需在多显示器下测量 |
| 识别 P50 | ≤ 1 秒 | 清晰常规单行公式 |
| 识别 P95 | ≤ 2 秒 | 不含首次模型下载，因为模型随包分发 |
| 冷模型加载 | 不阻塞菜单栏操作 | 可异步加载或首次触发加载 |
| 模型包体 | 约 60 MB | 目标值，待转换实测 |
| 网络请求 | 0 | 更新检查等非核心功能也不进入 v0.1 |

### 7.4 可维护性验收

- UI 不直接依赖 `MLModel`、`CGWindowListCreateImage` 或剪贴板 API。
- 模型更新只需替换 Recognition 实现或资源，不修改截图和 UI Core。
- 截图后端切换不修改识别模块。
- 关键状态机、坐标映射、预处理和 Tokenizer 有单元或 golden tests。
- App Target 中不出现大段业务协调代码。

## 8. 风险与决策点

| 决策点 | 何时决定 | 依据 |
|---|---|---|
| 固定画布还是官方尺寸预测器 | M1 | 精度、转换难度、包体和延迟 |
| 官方采样还是 Argmax | M1/M4 | 固定测试集完整正确率和稳定性 |
| Decoder 是否做 KV Cache | M4 后 | P95 延迟和内存，不为理论优化提前实现 |
| SwiftMath 或其他渲染方案 | M5 前 | 宏覆盖、性能、许可证和维护状态 |
| 模型是否量化到 8-bit | M6 | 包体收益与质量变化 |
| 是否需要模型微调 | v0.1 评测后 | 目标场景错误是否集中且无法由预处理解决 |

## 9. 完成定义

v0.1 完成意味着：用户在 macOS 13+ 任意应用中看到一行清晰印刷公式时，可以通过快捷键框选，在本机获得可检查、可修改、可复制的 LaTeX；整个流程不依赖网络，不会因重复触发或异步回调破坏当前会话。

它不意味着 pix2tex 已覆盖所有数学排版，也不意味着模型无需后续评测和微调。
