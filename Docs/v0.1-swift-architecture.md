# EqnSnap v0.1 Swift、Core 与 UI 架构

> 更新日期：2026-07-16  
> 文档状态：规划稿  
> 上位计划：[v0.1.md](v0.1.md)  
> 模型边界：[v0.1-integration.md](v0.1-integration.md)

## 1. 架构目标

本架构需要同时满足：

- v0.1 能快速完成截图识别主闭环。
- 截图、识别、展示和系统服务可以独立测试。
- 将来替换 pix2tex、截图后端或 LaTeX 渲染器时，不重写整个应用。
- SwiftUI 用于状态驱动界面，AppKit 用于截图覆盖窗口和浮动 Panel。
- 不为尚未进入范围的历史记录、云端模型或插件系统提前搭建空层。

在 Xcode App Target 之外建立本地 Swift Package：

v0.1 先保持一个 Package。只有构建时间、复用或发布边界出现实际问题时，再拆成多个 Package。

## 3. Targets 与依赖方向

```text
EqnSnapApplication
    ├── EqnSnapUI
    ├── EqnSnapPresentation
    ├── EqnSnapPlatform
    ├── EqnSnapRecognition
    └── EqnSnapCore

EqnSnapUI           → EqnSnapPresentation + EqnSnapCore
EqnSnapPresentation → EqnSnapCore
EqnSnapPlatform     → EqnSnapCore
EqnSnapRecognition  → EqnSnapCore
EqnSnapCore         → Foundation + Combine + CoreGraphics
```

约束：

- `EqnSnapCore` 不导入 SwiftUI、AppKit、CoreML、Vision 或 WebKit。
- `EqnSnapPresentation` 不直接访问屏幕、剪贴板或模型文件。
- `EqnSnapUI` 不创建具体 service，也不持有 `MLModel`。
- `EqnSnapApplication` 是唯一组合根，负责把具体实现注入工作流。
- Target 之间不允许反向依赖或循环依赖。

## 4. EqnSnapCore

### 4.1 职责

- 业务值类型和强类型标识。
- 工作流可观察状态所需的纯数据结构。
- 系统能力和识别能力的 ports。
- 统一错误类型。
- 临时截图的所有权与生命周期规则。

### 4.2 关键值类型

```swift
struct CaptureSessionID: Hashable, Sendable {
    let rawValue: UUID
}

struct DisplayID: Hashable, Sendable {
    let rawValue: UInt32
}

struct CapturedFormula: @unchecked Sendable {
    let sessionID: CaptureSessionID
    let image: CGImage
    let pixelSize: CGSize
    let scale: CGFloat
}

struct FormulaRecognitionResult: Sendable, Equatable {
    let sessionID: CaptureSessionID
    let latex: String
    let tokenCount: Int
    let timings: RecognitionTimings
    let modelVersion: String
}
```

`CGImage` 的并发标注需要依据实际使用方式审查。若无法证明跨 actor 使用安全，应把图片封装到受控 actor 或只传递不可变像素数据，而不是随意添加 `@unchecked Sendable`。

### 4.3 Ports

```swift
protocol PermissionPort: Sendable {
    func screenCaptureStatus() async -> ScreenCapturePermission
    func requestScreenCapturePermission() async -> Bool
    func openScreenCaptureSettings() async
}

protocol GlobalShortcutPort: Sendable {
    func register(_ shortcut: KeyboardShortcut) async throws
    func unregister() async
}

protocol DisplayPort: Sendable {
    func displayUnderPointer() async throws -> DisplayDescriptor
}

protocol CaptureBackend: Sendable {
    func captureDisplay(_ display: DisplayDescriptor) async throws -> CapturedDisplayFrame
}

protocol FormulaRecognitionPort: Sendable {
    func prepare() async throws
    func recognize(_ request: FormulaRecognitionRequest) async throws -> FormulaRecognitionResult
    func cancel(sessionID: CaptureSessionID) async
}

protocol PasteboardPort: Sendable {
    func writePlainText(_ value: String) async throws
}

protocol LatexRenderingPort: Sendable {
    func validate(_ latex: String) async -> LatexRenderValidation
}
```

`LatexRenderingPort` 只负责业务层的验证结果。真正的 `NSView` 或 SwiftUI 表现仍属于 UI 层。

### 4.4 错误模型

底层错误在模块边界映射为有限、可展示的错误：

```swift
enum EqnSnapError: Error, Sendable, Equatable {
    case screenCapturePermissionDenied
    case displayUnavailable
    case captureFailed
    case invalidSelection
    case modelResourceMissing
    case modelIncompatible
    case recognitionFailed
    case recognitionTimedOut
    case outputTooLong
    case pasteboardWriteFailed
}
```

日志可以保留底层错误描述，但 UI 不直接展示 Core ML 或 Core Graphics 的原始错误字符串。

## 5. EqnSnapPlatform

### 5.1 权限

`MacScreenCapturePermissionClient` 封装：

- `CGPreflightScreenCaptureAccess()`。
- `CGRequestScreenCaptureAccess()`。
- 打开系统设置中的屏幕录制页面。

v0.1 不把 Accessibility 权限设为前置条件。若后续加入窗口吸附，再单独增加新的 port 和权限说明。

### 5.2 全局快捷键

使用 Carbon `RegisterEventHotKey`，并封装为 `CarbonHotKeyClient`：

- 注册、替换和注销必须是事务性的。
- 新快捷键注册失败时继续保留旧快捷键。
- 回调只发送应用命令，不直接启动窗口或截图 API。
- 默认快捷键要避免与系统截图快捷键冲突，最终键位在 UI 实测后确定。

### 5.3 显示器和截图

建议保留两个后端：

- macOS 13：Core Graphics 静态截图后端。
- macOS 14+：`SCScreenshotManager` 后端。

两者都实现 `CaptureBackend`，输出统一的不可变 `CapturedDisplayFrame`。后端选择只发生在组合根。

截图准备流程：

```text
定位鼠标显示器
    → 获取显示器点坐标、像素尺寸和 scale
    → 捕获冻结画面
    → 在冻结画面上显示选区 overlay
    → 将点坐标选区映射到像素坐标
    → 从冻结画面裁切 CGImage
```

这样可以避免把 EqnSnap 自己的遮罩窗口截入图片，也避免用户松开鼠标后屏幕内容变化导致错位。

### 5.4 剪贴板

`MacPasteboardClient` 只写 `NSPasteboard.PasteboardType.string`。输出格式包装由 Presentation 层决定，Platform 不知道 LaTeX 语义。

## 6. EqnSnapRecognition

Recognition 是具体 pix2tex 实现，内部建议包含：

```text
Pix2TexRecognitionService actor
├── ModelBundleLoader
├── FormulaImagePreprocessor
├── Pix2TexEncoderRunner
├── Pix2TexDecoderRunner
├── Pix2TexTokenizer
├── LatexNormalizer
└── RecognitionMetricsCollector
```

约束：

- 模型按版本只加载一次。
- 同一时间默认串行执行一次识别，避免菜单栏工具瞬时占用过多内存。
- 预处理参数必须来自 manifest，不在 Swift 代码中散落魔法数字。
- Core ML 类型不越过 Recognition Target。
- Decoder 循环检查取消状态、EOS 和最大长度。
- 规范化只做经过测试的等价清理，不擅自改写用户公式。

详细流程见 [v0.1-model.md](v0.1-model.md) 和 [v0.1-integration.md](v0.1-integration.md)。

## 7. EqnSnapPresentation

### 7.1 工作流状态

```swift
enum WorkflowState: Equatable {
    case idle
    case checkingPermission(CaptureSessionID)
    case preparingCapture(CaptureSessionID)
    case selecting(SelectionState)
    case recognizing(RecognitionViewState)
    case presenting(ResultViewState)
    case failed(FailureViewState)
}
```

状态转换：

```text
idle
  → checkingPermission
  → preparingCapture
  → selecting
  → recognizing
  → presenting
  → idle

任意准备/选择状态 → idle                    取消
recognizing → failed → recognizing           重试
recognizing/presenting/failed → idle          关闭
```

### 7.2 WorkflowController

建议使用单个 `@MainActor final class FormulaCaptureWorkflow` 作为 UI-facing coordinator：

- 接收菜单栏和快捷键命令。
- 创建新的 `CaptureSessionID`。
- 驱动权限、截图、选区、识别和结果状态。
- 所有异步返回都先核对当前 session ID。
- 将耗时工作交给 injected ports，不在主线程运行推理。

不建议让每个 ViewModel 各自协调一部分生命周期，否则截图窗口、识别任务和结果窗口容易出现多个事实来源。

### 7.3 状态不变量

- `activeSessionID == nil` 时必须是 `.idle`。
- 只有 `.recognizing`、`.presenting` 和可重试 `.failed` 状态持有截图。
- `.presenting` 中只存在一份可编辑 LaTeX 真值；预览读取它，复制也读取它。
- 关闭会话先让 session 失效，再取消任务和释放资源。
- 旧任务完成时不得恢复已关闭窗口。

## 8. EqnSnapUI

### 8.1 菜单栏

使用 SwiftUI `MenuBarExtra`：

```text
截取公式…
──────────
设置…
关于 EqnSnap
退出 EqnSnap
```

v0.1 不显示没有实现的“历史记录”入口。菜单项调用 `FormulaCaptureWorkflow` 命令，不直接操作 AppKit service。

### 8.2 设置

SwiftUI `Settings` 场景首版包含：

- 快捷键展示或录制。
- 复制成功后是否关闭结果。
- 模型版本和许可证入口。
- 屏幕录制权限状态与系统设置入口。

没有实际需求前不增加主题、模型选择或云端账户设置。

### 8.3 截图 Overlay

使用 AppKit 无边框 `NSPanel`/`NSWindow` 承载选区视图：

- 窗口 frame 精确覆盖当前显示器。
- window level 高于普通窗口，但不改变其他应用布局。
- 半透明遮罩上显示冻结画面、选区和尺寸标签。
- 接收鼠标拖动、`Esc` 和光标变化。
- mouse-up 后立即提交有效选区。

选区逻辑应尽量是纯 reducer：

```swift
func reduce(state: inout SelectionState, event: SelectionEvent) -> SelectionEffect
```

View 只把 `mouseDown/mouseDragged/mouseUp/keyDown` 转换为事件。

### 8.4 结果浮层

结果使用 `NSPanel + NSHostingController<ResultPanelView>`：

- 可在其他应用上方显示。
- 不抢占不必要的应用焦点；进入源码编辑时允许成为 key window。
- 关闭、应用退出和新会话规则由统一 controller 管理。
- 面板尺寸紧凑，并对长 LaTeX 设置合理的最小/最大尺寸。

推荐布局：

```text
┌──────────────────────────────────────────┐
│ 原截图（固定高度、可横向适配）           │
├──────────────────────────────────────────┤
│ 渲染预览                                 │
├──────────────────────────────────────────┤
│ LaTeX 源码编辑器                         │
│                                          │
├──────────────────────────────────────────┤
│ 状态/耗时            重新识别  复制  关闭 │
└──────────────────────────────────────────┘
```

识别中先显示截图和进度状态，不创建第二个临时窗口。

### 8.5 LaTeX 预览

macOS 没有系统级 LaTeX 渲染控件。v0.1 推荐先评估 SwiftMath 类原生库，通过 `NSViewRepresentable` 接入 SwiftUI：

- 全离线，适合常用数学公式。
- 渲染器通过独立 adapter 隔离。
- 渲染失败时保留可编辑源码并显示轻量错误，不阻止复制。
- 发行前核对库许可证和支持的 LaTeX 子集。

若实际样本中的宏覆盖不足，再比较离线 KaTeX + `WKWebView`。不在业务状态中暴露具体渲染框架类型。

### 8.6 可访问性

- 所有图标按钮提供 accessibility label。
- 识别完成、复制成功和错误状态通过适当的 VoiceOver announcement 告知。
- 源码编辑器保持系统文本编辑行为。
- 不只依靠颜色表达加载、错误或选区状态。

## 9. EqnSnapApplication

App Target 只保留类似以下结构：

```swift
@main
struct EqnSnapApp: App {
    @NSApplicationDelegateAdaptor(AppDelegate.self) private var appDelegate

    var body: some Scene {
        MenuBarExtra("EqnSnap", systemImage: "function") {
            AppMenuView(container: appDelegate.container)
        }
        Settings {
            SettingsView(container: appDelegate.container)
        }
    }
}
```

`ApplicationContainer` 显式创建：

- 权限 client。
- 快捷键 client。
- 显示器和截图 backend。
- pix2tex recognition service。
- 剪贴板 client。
- workflow。
- overlay 与 result panel controller。

生命周期回调转发给这些对象，不在 `AppDelegate` 中实现业务判断。

## 10. 从 Snapio 迁移的边界

参考路径：

```text
../Snapio/Packages/SnapioKit
```

### 10.1 可迁移的最小子集

- 强类型显示器/坐标标识。
- `GeometryMapper` 和对应测试。
- 显示器信息适配器。
- macOS 13 Core Graphics 与 macOS 14+ ScreenCaptureKit 后端。
- Carbon 全局快捷键 client 和快捷键回滚逻辑。
- 全屏 overlay panel/window controller。
- 选区遮罩、边框、拖动输入和 `Esc` 处理。
- 临时图片所有权思想。

### 10.2 必须改造

- 权限门槛只保留屏幕录制。
- 删除窗口悬停、窗口捕获、移动、八向缩放和二次确认。
- mouse-up 直接输出裁切截图。
- CaptureCoordinator 出口改为 `FormulaRecognitionPort`。
- 临时资源 owner 改成 EqnSnap 的 recognition/result session。
- 菜单、设置、错误文案和 bundle 标识全部使用 EqnSnap 语义。

### 10.3 不迁移

- 标注、undo/redo、安全遮挡。
- 保存 PNG、书签和默认目录。
- 贴图、Quick Action 和窗口目录。
- Snapio 完整 AppCoordinator。
- Accessibility 双权限策略。

EqnSnap v0.1 不长期依赖完整 SnapioKit。先复制并保留来源注释与测试；等两个项目的截图核心稳定后，再决定是否抽取共同的 `ScreenSelectionKit`。

## 11. 测试设计

### 11.1 Core

- 状态机所有合法转换。
- 重复快捷键、关闭后回调、重试时旧任务回调。
- 无效选区、反向拖动、边界裁切。
- 资产在成功、失败、取消和关闭时的释放。

### 11.2 Platform

- 点坐标到像素坐标映射，包括 Retina 和不同显示器原点。
- 后端裁切区域与预期像素匹配。
- 快捷键替换失败时保留旧值。
- 权限状态映射和设置跳转 URL。

依赖真实系统权限的测试应与纯单元测试分开，避免 CI 被权限弹窗阻塞。

### 11.3 Recognition

- Python/Swift 预处理 fixture 对比。
- Encoder 输出和 Decoder logits 对比。
- BOS/EOS/PAD、最大长度和未知 Token。
- 取消、模型资源损坏和 manifest 版本不兼容。
- 固定图片的端到端 golden result。

### 11.4 Presentation/UI

- 使用 fake ports 测试 loading、success、failure、retry 和 close。
- 结果编辑后预览与复制读取同一字符串。
- UI tests 只覆盖关键窗口出现、Esc、复制等主路径，不复刻全部单元状态测试。

## 12. 扩展路径

未来功能应沿现有边界增加，而不是改写主链路：

| 未来需求 | 扩展位置 |
|---|---|
| 替换识别模型 | 新的 `FormulaRecognitionPort` 实现 |
| 云端回退 | Presentation 中显式策略 + 新 recognition adapter；需用户授权 |
| 历史记录 | 增加独立 persistence target 和 `RecognitionHistoryPort` |
| 多格式复制 | Presentation 的输出 formatter |
| 共享截图核心 | 抽取 `ScreenSelectionKit`，Platform/UI 同时迁移 |
| 更复杂结果窗口 | 扩展 Result feature，不让 Capture 依赖它 |

只有需求进入明确版本计划时才增加对应接口和 Target。
